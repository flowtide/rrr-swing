# 기억의 층과 주입 경로

세션에 기억을 넣는 경로는 둘이다. **무엇이 어디로 가는지는 변경 빈도가 정한다.**

| | 기동 컨텍스트 | 턴 컨텍스트 |
|---|---|---|
| 묻는 것 | **무엇을 지켜야 하고 어디서 왔는가** | **지금 무엇을 따라야 하는가** |
| 변경 빈도 | 주간(규칙) · 일 1회(일지) | 장중 수시 |
| 크기 | 예산 12,000자 | 상한 1,000자 |
| 주입 | 기동 1회, **시스템 프롬프트** | **매 턴**, 사용자 프롬프트 앞 |
| 수단 | `claude --append-system-prompt-file` | `UserPromptSubmit` 훅 |

한 층으로는 둘 중 하나를 잃는다. 기동 1회만 두면 스냅샷이라 장중 변화가 닿지 않고, 매 턴 전문을 넣으면 한글 12,000자 ≈ 6~8천 토큰 × 수백 턴이라 비싸다.

> **시스템 프롬프트는 그날의 기준이다. 장중에 바뀌지 않는다. 변화는 턴 컨텍스트가 나른다.**

장중에 몇 번을 재기동해도 같은 기준을 들고 뜬다.

## 저장 구조

파일명은 **전부 소문자**, 날짜는 `YYYY-MM-DD`. **"현재" = 각 디렉터리의 최신 날짜 파일.**

```
local/
  memory/                             ← 고치는 곳
    playbook/      2026-09-15.md      규칙          ┐
    state/         2026-09-15.md      상태·지시      ├ 원본. 사람·에이전트·세션이 고친다
    journal/       2026-09-15.md      서사          ┘
  system-prompts/  2026-09-15.md      ← 만들어지는 곳. 기동 산출물이며 손대지 않는다
```

규칙이 하나라 설명이 필요 없고, `journal/` 이 이미 이 모양이라 새 규칙이 아니라 기존 규칙의 확장이다.

**원본과 산출물은 같은 디렉터리에 두지 않는다.** 산출물은 매 기동 덮어써지므로, 고쳐도 남지 않는다. 나란히 놓으면 구조가 "여기도 고치면 되는 자리"라고 말한다 — 갈라 놓는 것이 그 오해를 없애는 가장 싼 방법이다. `local/memory/` 안의 것은 전부 고쳐도 되고, 그 밖의 것은 아니다.

### 하나의 편집 규칙

> **고치려는 날짜 파일이 없으면 최신을 복사해 만든 뒤 고친다.**

주체(사람·에이전트·세션) 무관, 층 무관. 안 고친 날은 파일이 생기지 않으므로 **파일의 존재가 곧 "이날 바뀌었다"는 기록**이 된다.

세션은 경로를 계산하지 않는다. 부트 프롬프트가 알려준다:

```
오늘의 원본: local/memory/{playbook,state,journal}/2026-09-15.md
없으면 각 디렉터리의 최신 파일을 그 이름으로 복사한 뒤 고친다.
```

**과거 파일은 고치지 않는다.** 그날 세션이 무엇을 들고 무엇을 보았는지가 복기의 증거다. 고칠 것이 있으면 오늘 날짜 파일에 쓴다.

### `## 운영자 지시`

`state/` 안의 한 절이다. 오늘의 지시는 오늘 상태의 일부다.

**세션은 이 절을 지우거나 고치지 않는다. 읽고 따른다.** 세션은 상태를 하루에도 수십 번 덮어쓰므로, 이 한 줄이 없으면 운영자가 적은 지시가 다음 갱신에 사라진다.

이 절은 두 경로 **모두**에 실린다 — 기동 시 맨 앞에, 그리고 매 턴.

## 기동 컨텍스트

기동할 때 세 원본의 최신을 머지해 `system-prompts/<오늘>.md` 로 쓰고, 그 파일을 시스템 프롬프트에 붙인다.

**담는 순서가 곧 우선순위다.** 예산은 앞 절부터 소진되므로 뒤 절이 먼저 굶는다.

```
## 운영자 지시      state/ 에서 끌어올린다
## 규칙             playbook/ 최신
## 상태             state/ 최신(운영자 지시 절 제외)
## 최근 일지        journal/ 최신 N개, 최신부터
```

지시를 맨 앞에 두는 것은 그것이 규칙보다 먼저 읽혀야 하기 때문이다. 끌어올림은 **절 이름으로 고르는 것**이지 요약이 아니다 — 본문은 그대로 옮긴다.

일지 절 안에서도 최신 일자를 먼저 담는다. 오래된 것부터 담으면 예산이 빠듯할 때 오늘 일지가 먼저 잘린다.

예산 `memory.load_budget_chars`(12,000) · 파일당 `memory.file_cap_chars`(4,000). 통째로 빠진 절은 끝에 `[예산 소진 — 읽지 못한 절: …]` 를 남긴다. 빠진 것과 원래 비어 있던 것이 같아 보이면 세션이 "규칙이 없다"고 읽는다.

**산출물은 읽기 전용 기록이다.** 사람이 고칠 자리가 아니다 — 고쳐도 다음 기동에 덮어써진다. 고칠 것은 원본에 쓴다. 같은 날 재기동하면 원본이 그새 바뀌었을 수 있으므로 다시 머지한다.

**시스템 프롬프트로 넣는 이유**: 사용자 메시지는 대화가 길어지면 요약되거나 밀려난다. 규칙과 운영자 지시가 그렇게 사라지면 안 된다. 시스템 프롬프트는 압축 대상이 아니다.

## 턴 컨텍스트

**내용**(상한 1,000자, 앞이 우선):

1. `config.mode`
2. `state/` 최신의 `## 운영자 지시`
3. `state/` 최신의 `## 태도`
4. `state/` 최신의 `## 열린 협의`
5. 그 파일의 최종 수정 시각

**고르는 기준**은 매 턴 필요하면서 자주 바뀌는 것. 보유는 종목·수량이 잘 안 바뀌고 가격은 세션이 조회한다. 메모는 급하지 않다. 장세는 세션이 30분마다 직접 본다.

**요약하지 않는다.** 지정된 절을 그대로 싣고 상한에서 자르기만 한다. 무엇이 중요한지 고르는 것은 판단이고, 판단은 세션의 일이다. 코드는 절 이름으로 고르고 길이를 맞춘다.

**원천이 `state/` 인 이유**: 세션이 이미 유지하는 단일 진실이다. 별도 파일을 두면 갱신을 잊는 순간 두 기억이 갈린다.

상한을 넘기 시작하면 상한을 올리지 말고 `## 태도` 를 줄인다. 매 턴 실리는 값이다.

## 하루의 흐름

```
장중        세션이 state/<오늘>.md 를 고친다 → 다음 턴부터 턴 컨텍스트에 실린다
            운영자가 지시하면 `## 운영자 지시` 에 적는다 → 같은 경로로 즉시 반영
15:30 마감
20:30       marks.py    (운영자 크론)
20:35       flags.py    (운영자 크론)
마감 절차    세션이 journal/<오늘>.md 를 쓴다
            사람 또는 에이전트가 내일 것을 준비한다 — 규칙이 바뀌었으면
            playbook/<다음 거래일>.md, 지시가 있으면 state/<다음 거래일>.md
다음 기동    start.sh 가 세 원본의 최신을 머지해 주입한다
```

준비를 건너뛰어도 세션은 뜬다 — 최신 원본이 그대로 유효하기 때문이다. 별도의 초안 생성도, 편집 창도 없다.

## 실패 처리

| 상황 | 동작 |
|---|---|
| 원본이 하나도 없음(최초 설치) | **기동 중지** — `bin/init_local.sh` 를 안내한다 |
| 오늘 날짜 원본 없음 | 최신을 쓴다. 복사는 고치는 쪽이 한다 |
| 절이 예산에 굶음 | 끝에 `[예산 소진 — 읽지 못한 절: …]` |
| 턴 컨텍스트의 지정 절이 없음 | 그 자리에 `(없음)` |
| 훅 실패 | 턴은 진행한다 — 컨텍스트가 없다고 세션을 막지 않는다 |

기동을 막는 자리는 하나뿐이다. 원본이 사람이 쓴 것이고 머지가 결정적 함수이므로, 그 외에 검토를 강제할 대상이 없다.

## 배선

```
bin/start.sh ⑤   context_load.py → local/system-prompts/<오늘>.md
bin/start.sh ⑥   exec claude --append-system-prompt-file local/system-prompts/<오늘>.md … -- "$BOOT"
.claude/settings.json   UserPromptSubmit 훅 → bin/turn_context.py
```

`.claude/settings.json` 은 **훅만** 담는다. MCP 설정은 넣지 않는다 — MCP 는 운영자의 user scope 등록을 그대로 쓴다.

`$BOOT` 에는 기억을 싣지 않는다. 기동 순서·도구 목록·오늘 원본 경로만 남고, 기억은 시스템 프롬프트가 들고 있다.
