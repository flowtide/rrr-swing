## 2. 정의(고정)

- **큰손**: 체결 1건 금액 1억 원 초과(`upper_amount_won > 1억`) 구간의 매수 금액 − 매도 금액. 대조군 개미 = 1천만 원 이하 구간.
- **큰손 흡수 ① (H1)** = `whale_ratio ≥ +0.4`(또는 ≤ −0.4) **이고** `same_ex × 방향 ≤ 0`(종목이 그 5분봉에 KOSPI 대비 그 방향으로 못 갔다).
  - *메커니즘*: 단일 5분봉 내에서 대규모 매도벽을 큰손이 아래에서 전부 체결(흡수)시켜 매도벽 소진 후 단기 반등 유발.
- **숨은 매집/분산 ② (H4)** = `whale_cum_ratio ≥ +0.20`(또는 ≤ −0.20) **이고** 종목 당일 누적 초과수익 부호가 반대(`sgn(cum_ex) * 방향 == -1`).
  - *공학적 수식*: 장 개장 후 누적 거래대금 대비 1억 초과 체결 순매수 비율이 20% 이상 쌓였으나, 주가의 당일 누적 초과수익률(`cum_ex`)은 지수 대비 마이너스(약세).
  - *시장 메커니즘 ("왜 숨은 매집인가")*:
    - **외형적 차트**: 지수 대비 빌빌거리거나 마이너스에 머물러 일반 투자자 눈에는 "오늘 약세 종목"으로 인식되어 매도 심리가 유발됨.
    - **이면의 수급**: 큰손은 호가를 위로 쳐올려 가격을 띄우지 않고, 쏟아지는 매도 물량을 아래에서 조용히 받아내며 하루 종일 수십~수백억 원의 물량을 집중 매집.
    - **귀결 (스프링 효과)**: 매도 물량이 소진되는 장 후반, 당일 KRX 정규장 마감 종가(15:30) 및 NXT 야간 종가(20:00)로 갈수록 지수와의 괴리를 좁히며 강력한 키맞추기 폭등으로 귀결됨 (2일 누적 KRX 종가 95% +36.5bp, NXT 종가 100% +42.9bp).
- **'큰손 흡수(H1)' vs '숨은 매집(H4)' 비교**:
  - `큰손 흡수(H1)`: **단일 5분봉(순간 포착)** 단위. 5분봉 거래대금 40% 이상 순매수 & 그 봉 초과수익 $\le 0$. 호가 단위 즉각 반등 모멘텀.
  - `숨은 매집(H4)`: **당일 전체 누적(장 시작~현재)** 단위. 하루 종일 지수 대비 억눌린 상태에서 대량 매집이 진행된 구조적 불일치. 장중 6봉·12봉 단기 반응보다 **정규장 종가 및 야간 세션 귀결**에서 가장 강력한 알파 분출.
- **투자자 조건** = 사건 봉의 외국인/기관 당일 누적 부호가 큰손 방향과 같음/반대.
- **대조군(분위수 매칭)** = 유효 봉 전체에서 큰손 `|whale_ratio| ≥ 0.4` 가 차지하는 분위수 q 를 구해, 개미·중간의 `|ratio|` 분포에서 같은 q 의 임계를 쓴다. 대조군 흡수 = 같은 정의(같은 봉 초과수익 ≤0)를 그 임계로.
- **결과 및 종가 평가 기준** = 다음 6봉(30분)·12봉(60분) 초과수익률의 부호 일치율과 평균(bp), 그리고 **당일 KRX 정규장 종가(15:30)** 및 **NXT 야간 종가(20:00)** 초과수익률 부호 일치율과 평균(bp).
  - 통과 = 사건 ≥ 30 에서 6봉 일치율 ≥ 60% **이고** 개미 대조군 같은 정의가 55% 미만 **이며**, 정규장 종가(KRX) 또는 야간 종가(NXT)에서 신호가 되돌려지지 않고 지속됨을 확인.

### 3.1 H1 대조군 기준의 문제 — 두 번째 거래일 분석 전에 고정할 것

09-16 표본에 분위수 매칭 대조군을 적용하면 개미 흡수도 6봉 63%(사건 67), 중간 60%(48)로 "<55%" 를 넘는다. 큰손은 74%·+15.4bp, 개미 +4.7bp, 중간 +1.5bp.
즉 "사는데 가격이 안 오른 봉 뒤에 오른다" 는 어느 층에서든 나는 현상이고, 큰손은 **크기**로만 구분된다. 원래 기준을 기계적으로 적용하면 H1 은 미달이다.
선택지(운영자가 하나를 고르고, 고른 뒤에는 바꾸지 않는다):
- (가) 원안 유지 — 개미 대조군 <55%. 09-16 기준 H1 미달.
- (나) 상대 기준 — 큰손 6봉 일치율 − 개미 ≥ 10%p **이고** 큰손 평균 bp > 개미 평균 bp. 09-16 기준 충족(74−63=11%p, 15.4 > 4.7).
- (다) 크기 기준 — 큰손 6봉 평균 초과수익 ≥ +10bp 이고 개미 ≤ +5bp. 09-16 기준 충족.
고르기 전까지는 (가)로 채점한다.

## 5. 운영 — 매일 남겨야 하는 것

rrr 은 2거래일만 보존하므로 아래 세 수집기의 스냅샷이 없으면 검정 자체가 불가능하다. 상시 크론에 두는 것은 운영자 몫이다.
`scripts/research/start_daily.sh` 가 아래를 묶는다: `start`(장 전, 유니버스를 gw watch-groups 에서 받아 3종 detach, 15:45 종료) · `post`(마감 후 글로벌 market-context 수신+집계 3종) ·
`schedule`(그날 08:50 start / 15:50 post 원샷 대기 프로세스, 크론 아님) · `universe`(점검).

```bash
# rrr-swing 에서, 장 시작 전
python3 bin/detach.py python3 scripts/research/ob_sampler.py --mode detail --symbols <KOSPI csv> --out local/research/orderbook/<date>/detail
# 공급자 환경에서(토큰은 공급자의 읽기 전용 미러 파일 읽기, 발급 없음)
(set -a; . ./.env; set +a; python3 "${RS_DIR}/bin/detach.py" ./.venv/bin/python "${RS_DIR}/scripts/research/market_sampler.py" --interval 60 --out "${RS_DIR}/local/research/orderbook/<date>/market")
# 마감 후
curl -H "X-API-Key: …" "$GW/api/market-context?bars=0" > local/research/orderbook/<date>/global_market_context.json
python3 scripts/research/panel_analyze.py --out local/research/orderbook/<date> --date <date>
```

주의: `kiwoom-sdk` `client.sector.net_purchase()` 와 MCP `kiwoom_sector_net_purchase` 의 `mrkt_tp` 기본값은 `'P00101'`(ka90005 관례)인데 ka10051 스펙은
코스피 `'0'`/코스닥 `'1'` 이다. 항상 명시한다. 기본값 수정은 kiwoom-sdk 쪽 결정.

## 7. 진행 순서와 경계 — 합의된 것

봉과 패널의 단위는 5분이다. 바뀌는 것은 Kiwoom REST 를 부르는 주기뿐이다.

1. **파일 수집(연구).** ka10051·ka90005 는 1분 폴링(`market_sampler.py --interval 60`), 값은 `rrr-swing/local/research/orderbook/<date>/` 에 원문으로 남긴다.
   Redis 에는 넣지 않는다. rrr 은 건드리지 않는다. 종목 투자자(ka10059)는 rrr 의 90초 수집을 그대로 읽고 폴링 대상이 아니다(값이 20분~2시간에 한 번 바뀐다).
   기다림은 없다. 격자에서 받고 봉의 확정 여부는 데이터의 플래그(`is_partial`·`as_of`·`sampled_at`)로 읽는다.
   - 주기를 바꿔도 값의 뜻은 같다(당일 누적 스냅샷 / 1분 버킷 누적). 달라지는 것은 봉 끝 정렬 오차(5분→1분)와 5분 증분의 정확도다.
   - 장중 투자자 수치는 잠정치라 뒤로 가는 점프가 보일 수 있다. 패널에는 "봉 끝 시점에 발표돼 있던 값"을 붙이고, 마감 후 최종값은 따로 둔다.
   - 종목 투자자 축은 "마지막 변화 시각"을 함께 남기고 당일 누적의 부호로만 쓴다.
2. **5거래일 검정(§3).** 사건 단위로 세고, 통과선은 미리 적은 것을 쓴다. 미달이면 규칙 후보로 올리지 않는다.
   이 단계에서 rs-lead 에는 아무것도 보내지 않는다. 매 봉 평가는 하더라도 로그만 남긴다(실시간 신호 ↔ 사후 재계산 대조용).
3. **승격(공급자 결정).** 통과한 축만 rrr producer 로 옮겨 Redis 와 `/market-context` 에 싣는다. rs-lead 는 그때 `decision_packet` 으로 받는다.
   - 5분 업종 축은 rrr 이 이미 5분마다 부르는 ka10051 의 버리는 행을 슬롯에 저장하면 추가 호출 0 이다.
   - 1분이면 rrr 의 `MarketFlowPoller`(슬롯당 1회, 종료+5초) 설계와 다르므로 별도 샘플러이거나 poller 의미 변경이다.
   - rrr 보존은 2거래일이다. 연구 축적은 승격 뒤에도 파일이다.

경계: 연구 산출물은 rrr-swing 안의 파일과 문서에만 있고, rrr·kiwoom-sdk·rrr-gw 는 변경하지 않는다. KOSPI 종목만 다루고 지수는 KOSPI 하나다.

열린 결정(운영자):
- 세 수집기를 매일 장 전에 띄우는 크론(§5). 없으면 5거래일 표본이 쌓이지 않는다.
- `kiwoom-sdk` `client.sector.net_purchase()` 와 MCP 도구의 `mrkt_tp` 기본값 `'P00101'` → ka10051 스펙 `'0'` 수정 여부.
- 승격 시점에 rrr 에 싣는 축의 범위(업종 행 저장 / ka90005 1분 시계열 / 둘 다).

## 8. 파일의 흐름 — 누가 만들고 누가 읽는가

아무도 전달하지 않는다. 수집기가 디스크에 원문을 쌓고, 읽는 쪽이 필요할 때 끌어간다.

```
[원천]                         [수집기: 격자에서 원문 저장]                          [파일: rrr-swing/local/research/orderbook/<date>/]

(rrr 토큰 미러  ka90005 ─┴─▶ market_sampler.py (rrr venv, --interval 60) ─────────▶ market/ka90005_merged.json   (cntr_tm 병합)
 읽기 전용, 발급 없음)                                                               market/sampler.log

rrr-api ──(gw /api/*)── /detail ──▶ ob_sampler.py --mode detail (300초) ──────────▶ detail/<HHMMSS>/<sym>.json   (candles·trade_buckets·investor_flow·orderbook_bars)
                        /market-context?bars=0 ─┐
                        /events ────────────────┴▶ ob_sampler.py (300초) ────────▶ <HHMMSS>/<sym>.json, events.jsonl

                                         panel_analyze.py ─▶ panel_<date>.jsonl ─▶ 집계 stdout ─▶ 이 문서 §4
                                         ob_analyze.py / whale_analyze.py ────────────────────▶ docs/08, 이 문서
```
