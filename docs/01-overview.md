# rrr-swing 개요 — 목적과 개념 한눈에

> 이 문서가 상위다. 세션 계약(`AGENTS.md`)과 코드는 이 문서를 따른다. (경로는 `rrr-swing` 작업 디렉터리 기준)

## 1. 목적 — 한 줄

**rrr-swing 은 한 계좌를 맡은 전문 스윙 트레이더다.** 시장의 흐름과 종목의 이야기를 알고, 자기 판단으로 베팅하고, 결과를 기록하고, 배운다.
규칙표를 실행하는 기계가 아니다. 규칙은 트레이더가 스스로 세우고 고친다.

## 2. 네 주체와 원칙

```
  운영자(사람) ─── 콘솔 대화 · 손절 협의 · 주간 미팅 · 급정지 ───┐
                                                                 ▼
  공급자 rrr ── 이벤트·시세·수급 ──▶  트레이더(LLM)  ──▶ 코드(장부 · 사후 보고)  ──▶ 키움 계좌
                 (증거만)               (판단 전부)          (판단 없음)
```

| 주체 | 하는 일 | 하지 않는 일 |
|---|---|---|
| **트레이더(LLM)** | 상황 인식, 가설, 진입·청산·수량·시점, 한도와 손절 정책, 기록, 복기 | MCP로 주문 실행 |
| **코드** | 이벤트 전달, 장부 기록, 사후 보고, 급정지(gw 키 비활성화) 집행 | 가격·수급을 이유로 판단을 막거나 바꾸는 일 |
| **운영자(사람)** | 사후 감독, 손절 협의, 주간 미팅에서 전략 변경 합의, 급정지 소유 | 건별 승인 |
| **공급자 rrr** | 5분봉 지지/저항 이벤트 6종 + heartbeat, macro, `/context`·`/flow` 측정값 | 추천·점수·주문 |

## 3. 이벤트가 세션에 닿는 길

공급자는 누가 무엇을 보는지 기억하지 않는다. 그건 **감시 목록** 하나가 정하고, 어댑터가
이벤트마다 그 파일을 확인한다.

```
  공급자 rrr ─── 전량 방송 ───▶  GET /api/events/stream      (쿼리 0개 · SSE push)
                                          │
                                          ▼
                 ┌────────────────────────────────────────┐
                 │  인바운드 어댑터 — 배달만, 판단 0       │
                 │                                        │        local/watchlist.json
                 │   ① mtime 확인 → 바뀌었으면 재읽기 ────┼──읽기──▶ {                    
                 │                                        │          "006800": {"note":…} 
                 │   ② sym 이 목록에 있나?                │         }                     
                 │       ├ 있다      → 봉 단위로 합쳐 배달│              ▲
                 │       ├ 없다      → 버림(delivery.jsonl)              │
                 │       └ sym 없음  → 배달(시장 전체)    │              │ 쓰기
                 └───────────────────┬────────────────────┘              │
                                     │  [digest account=… bar_ts=… n=2]  │
                                     ▼                                   │
                              트레이더(LLM)                               │
                                     └── bin/watchlist.py set|add|drop ───┘
```

| 규칙 | 근거 |
|---|---|
| **필터는 종목뿐** | `evt`·`sess`·시각으로 거르지 않는다. `sess` 는 주문정책용 값이다(장전=지정가만·본장=SOR·동시호가=취소만). 세션·만료로 거르면 마감 뒤 좁힌 값이 다음 거래일까지 살아남는다 |
| **목록은 이벤트마다 읽는다** | 고치면 다음 이벤트부터 반영. 기동 시 1회 고정하면 세션이 자기 눈을 런타임에 고칠 수 없다 |
| **언제나 현시점부터** | 재개 지점을 두지 않는다 — 지나간 봉은 실시간 판단에 쓸모가 없다. 끊긴 사실만 `local/inbound.log` 에 `gap=not_replayed` |
| **목록 이상은 알린다** | 파일 부재·손상·종목 코드 아닌 항목 → `[watchlist-problem …]` 하루 1회. 빈 목록은 의도이므로 조용하다 |

목록 파일이 경계다 — 세션은 쓰기만, 어댑터는 읽기만 한다.
